# mbedded.ninja 中文翻译风格指南

## 总体原则

- 目标读者是具备工科背景的工程师；译文要准确、简洁、可查证，不追求文学化。
- 同一概念全站使用唯一译法，以 `zh/glossary/terms.csv` 为准。
- 遇到术语表没有的词，先写入 `terms.proposed.csv`，不要各自发挥。

## 术语排版

1. 术语首次出现：`中文（English）`，例如“开漏（open-drain）”“上拉电阻（pull-up resistor）”。
2. 同一页面后续只写中文，不再重复括注。
3. `keep_en=true` 的术语必须括注；`keep_en=false` 的术语可只写中文。
4. 协议名、总线名、寄存器名、信号名保持英文：I2C、SPI、UART、SCL、SDA、GPIO、AHB、APB。
5. 代码标识符、函数名、宏、型号、封装代号保持原文：`HAL_GPIO_WritePin`、STM32F103、SOT-23、0402。
6. 单位保持国际符号：V、mA、µF、kHz、°C；数字与单位之间按中文排版留半角空格（如 `3.3 V`），公式内不改。
7. 人名、公司名、产品名保留原文。

## 句子与标题

- 标题用中文陈述式，避免“的”字堆叠；不要逐字直译英文标题。
- 英文祈使句译为中文祈使句；第二人称统一用“你”，不用“您”。
- 英文被动语态可转为中文主动句；不要生造“被进行”结构。
- 长句按中文习惯拆分，但不得改变技术含义。

## 代码与公式

- 代码块、行内代码的内容不翻译，包括注释（首期保持原样）。
- 数学公式不改；`\text{}` 内的自然语言首期也不改，避免渲染风险。
- 变量名、下标、单位宏（`\unit{}`）保持原样。
- 代码块数量、顺序、语言标记与原文一致。

## 图片与表格

- 图注翻译；图内英文保留，不重制图片。
- 表格表头翻译；数据、型号、单位、寄存器位名不译。
- 图片 `width` 必须带 `px`；不修改 `import('./_assets/...')` 路径。

## 链接与脚注

- URL 不改；链接文字可翻译。
- 脚注 key 不改；脚注正文翻译。
- 跨页链接指向原 slug；中文站由 `/zh` 路由承接。

## 常见禁用变体

- `open-drain` → 开漏，不用“开漏极”“开漏输出级”（除非原文是 open-drain output）。
- `pull-up` → 上拉，不用“拉起”。
- `decoupling` → 去耦，不用“解耦”。
- `slew rate` → 压摆率，不用“转换速率”。
- `layer stackup` → 层叠结构，不用“叠层”。
- `linker script` → 链接脚本，不用“链接器脚本”。
- `interrupt service routine` → 中断服务程序，首现括注 ISR。
- `volatile` 作为 C 关键字保持英文，不译“易失”。

## 提交前

```bash
npm run zh:check -- <file>
npm run zh:status
```

checker 必须 0 error；status 必须为 current。
